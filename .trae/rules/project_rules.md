# 项目规则

本项目的共享规范位于仓库根目录 `AGENTS.md`。开始任务时先完整读取该文件，再读取与本次修改相关的产物目录。

## 生效范围

本规则对整个仓库生效，始终加载。模块级细则写在 `AGENTS.md` 的「目录职责」和「改动边界」两节，不在本文件重复。

## 位置约束

- 原型只放在 `prototype/`，入口是 `prototype/index.html`，PC 端是 `prototype/pc.html`，手机端是 `prototype/mobile.html`。不新建 `prototype/v2/`、`prototype-new/` 这类平行目录。
- 流程图只放在 `diagrams/`，命名沿用 `序号-主题.svg`，被规格书以相对路径引用。
- 业务规格书只有一份：仓库根目录 `unique-业务规格说明书.md`。不新增同名的第二份规格书，也不拆分出多个副本。
- 配置与脚手架只放在 `.trae/`、`.github/`、`scripts/`。不新增构建工具链、包管理文件或应用源码目录。
- 临时截图放 `.screenshots/.tmp/`（已被忽略）；需要留存的截图才放 `.screenshots/` 并提交。

## 产物约束

- 原型保持纯静态：单 HTML 文件、内联 CSS 与 JS、无外部 CDN、无后端请求、数据仍为前端 mock。
- 原型里的页面结构、状态名、字段名、文案以 `unique-业务规格说明书.md` 为准，冲突时先确认业务口径再改。
- 修改 `prototype/pc.html` 的锚点时，同步维护 `#x → id="page-x"` 这条路由约定，导航、卡片、正文链接一起检查。
- 修改 `diagrams/` 下的 SVG 时，同步核对规格书中引用该图的位置是否仍然成立。
- 文档与代码中的中文使用 UTF-8，提交前确认没有乱码字符。

## 验证约束

- 提交前必须执行 `python scripts/check_assets.py` 并通过；CI 执行的是同一个脚本。
- 脚本覆盖不到的部分（原型交互、SVG 视觉、规格书可读性）在 PR 中用截图或打开方式说明，不用"已检查"这类空话代替。
- 失败就报失败，不通过放宽检查、忽略错误或跳过文件制造通过。

## 交付约束

- 每个 Issue 一个分支，默认交付到草稿 PR，不自行合并 main。
- PR 用 `Refs #编号` 关联工作项，写清改动范围、验证证据和未解决事项。
- 合并与发布需要明确授权；未获得授权时停在可审查的 PR。

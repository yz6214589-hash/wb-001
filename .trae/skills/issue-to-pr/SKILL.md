---
name: issue-to-pr
description: 处理明确指定的 GitHub Issue，改动 HTML 原型、SVG 流程图或业务规格书，交付经过验证的草稿 PR。
---

读取目标 Issue 正文、评论、父任务与依赖，读取仓库根目录 AGENTS.md 与 .trae/rules/project_rules.md。
确认验收条件、改动边界（改哪些文件、明确不动哪些文件）以及规格书中对应的章节。
只对影响实施的业务歧义提问，其余合理选择在 PR 中说明后推进。

按 Issue 查询是否已有对应分支和所有状态的 PR，避免重复开工。
已有成果先核对归属和状态，续作或报告已完成，不强制重置、不重建同名分支。
新任务从远端最新 main 创建分支，分支名使用 ai/issue-编号，不把当前工作区的未提交改动带进来。

按产物类型执行改动：
- HTML 原型：只改 prototype 下对应文件，保持单文件纯静态、内联 CSS 与 JS、不引外部资源；新增或改动锚点时同步维护 #x 对应 id="page-x" 的路由约定，导航、卡片与正文链接一起核对。
- SVG 图：保持 xmlns 与 viewBox 完整，文本在图中可读；改变图的语义时同步核对规格书中引用该图的位置。
- Markdown 规格书与 README：按现有章节编号就地修改，不新增副本、不重排编号；引用图片使用相对路径，且文件真实存在。

调用 verify-change 技能完成验证。
验证成功后提交、推送并创建或更新草稿 PR。
创建前核对目标仓库、head 分支与 base 分支，默认合入 main。
验证未通过或环境阻塞时明确标记阻塞，可以保留草稿 PR 供审查，但不能宣称通过。

PR 按仓库模板填写：变更说明、改动范围、验收条件勾选、Refs #编号、验证证据（脚本输出、CI 运行链接、原型截图或打开路径）。
完成后输出 Issue 链接、分支名、PR 链接、提交 SHA 和剩余事项。
遵守现有授权，默认只交付到草稿 PR，不自行合并 main、不发布。
